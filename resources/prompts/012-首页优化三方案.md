# 012 · 首页优化三方案

首页是评审进应用的第一个落地页，也是"平台使用深度"的门面。当前版本功能完整，但存在五处结构性问题。本文档给出三套可选改造方案，供拍板后实施。

## 一、现状量化诊断

实测环境：1440×900 视口，本地服务 127.0.0.1:8123。

| 项目 | 实测值 | 说明 |
|------|--------|------|
| 文档总高 | 1176px | 超出视口 276px，需滚动 |
| hero 区 | 108px 高 | 占满 1166px 宽，内容仅 34 字副标题，两端大量留白 |
| 能力卡区 | 398px 高 | 三卡并排 |
| 典型场景 + 最新告警 | 381px 高 | 场景 309px / 告警 94px，右侧空置约 200px |
| 核心指标卡 | 不存在 | `.home-metrics-card` 已移除，四个指标挤在三张能力卡的描述文字里 |

### 五个具体问题

**1. 能力截图被裁切变形（最严重）**

三张实拍图的原始尺寸与渲染尺寸：

| 文件 | 原始 | 渲染 | 宽高比偏差 |
|------|------|------|-----------|
| cap-detect.png | 1180×588 | 376×189 | 2.01 vs 1.99，轻微 |
| cap-attr.png | **1300×2472** | 376×189 | **0.53 vs 1.99，严重失真** |
| cap-verify.png | 2012×1328 | 376×189 | 1.52 vs 1.99，右侧被裁 |

`cap-attr.png` 是纵向长图（手机竖屏比例），塞进 2:1 的横向容器后，`object-fit: cover` 只截取了中间一小段。评委看到的是一段被拦腰截断的界面，看不出归因结论长什么样。

**2. 核心指标缺少独立位置**

`.home-metrics-card` 在上一轮重构中被移除，识别准确率 94.44%、根因定位 94.68%、建议可执行率 100%、闭环降幅 25.64% 这四个数字，现在分散在三张能力卡的描述文字里。评审要在三张卡里逐个扫才能拼出"这系统做得怎么样"。

**3. 右下角空置**

「典型场景」高 309px，「最新告警」高 94px 并排在同一行，告警只有两条撑不满，右侧留下约 200×309px 的空白。

**4. 主 CTA 冲突**

hero 区一个「开始使用 →」，三张能力卡各有一个「进入检测 → / 进入归因 → / 进入闭环 →」，共四个入口同时争夺注意力，用户不知道主线是哪个。

**5. hero 内容密度不足**

108px 高的横幅里只有标题加一句 34 字副标题和按钮，两侧留白严重，深色背景下一片空旷。

## 二、三套方案

### 方案 A · 任务优先型（推荐）

**核心主张**：用户进门第一个问题永远是"我现在该干什么"，首页第一屏直接回答它。

**结构**

```
┌────────────────────────────────────────────────────────┐
│ 钢材表面质量缺陷智能归因与闭环处置平台        [开始使用 →]│  ← 压缩到 72px
├──────────────────────────┬─────────────────────────────┤
│ 当前进度  第 2 / 5 步     │  核心指标                   │
│ 去归因诊断                │  94.44% 94.68% 100% 25.64%  │  ← 四宫格独立
│ 样件已载入，接下来定位根因 │  点击查看分析看板 →         │
│ [去归因诊断 →]            │                             │
├──────────────────────────┴─────────────────────────────┤
│ ┌──────────┐ ┌──────────┐ ┌──────────┐                  │
│ │ 能力图 1  │ │ 能力图 2  │ │ 能力图 3  │                  │  ← 三卡并排
│ │ 缺陷识别  │ │ 根因归因  │ │ 整改闭环  │                  │     CTA 降为文字链
│ │ [截图]    │ │ [截图]    │ │ [截图]    │                  │
│ │ 94.44%    │ │ 94.68%    │ │ 25.64%    │                  │
│ │ 进入 →    │ │ 进入 →    │ │ 进入 →    │                  │
│ └──────────┘ └──────────┘ └──────────┘                  │
├──────────────────────────┬─────────────────────────────┤
│ 典型场景（2×2 网格）      │ 最新告警（最多 5 条）        │  ← 等高对齐
└──────────────────────────┴─────────────────────────────┘
```

**关键改动**

- hero 高度从 108px 压到 72px，标题字号从 20px 降到 18px，副标题压到 26 字以内
- 新增「当前进度卡」，数据源直接复用顶部指引条的 `JOURNEY` 常量与 `flowDone` 状态，不新增任何状态逻辑
- 四个核心指标恢复独立四宫格卡片，整体可点击跳分析看板
- 三张能力图的 `object-fit` 改为 `contain` + 浅色底衬，同时**重新截图时按 2:1 横向比例裁切原图元素区域**，不再让 CSS 强裁
- 能力卡 CTA 从实心/幽灵按钮降为纯文字链「进入 →」，唯一主按钮留在 hero
- 典型场景改 2×2 网格（每格图标 + 标题 + 一行描述），告警限 5 条，两栏等高

**预期结果**：文档总高从 1176px 降到约 860px，首屏无需滚动即可看到进度、指标、能力图三块核心内容。

**改动量**：index.html 结构调整 + CSS 约 120 行 + app.js 约 40 行（进度卡渲染 + 能力图重截）。

### 方案 B · 叙事门户型

**核心主张**：首页首先是一份产品说明，讲清楚这是什么、解决什么、怎么用，其次才是入口。

**结构**

```
┌────────────────────────────────────────────────────────┐
│                                                ┌──────┐ │
│  钢材表面质量缺陷智能归因与闭环处置平台         │      │ │
│  识别 · 归因 · 整改 · 复检，四步闭环              │ 大图  │ │  ← hero 280px
│  [开始使用 →]  [查看能力图示 ↓]                  │      │ │
│                                                └──────┘ │
├────────────────────────────────────────────────────────┤
│  ①检测 ──── ②归因 ──── ③工单 ──── ④整改 ──── ⑤闭环      │  ← 横向时间线
├────────────────────────────────────────────────────────┤
│  ┌──────────────────────────────────────────────┐    │
│  │  大图 1 缺陷识别：真实运行截图                 │    │  ← 三大能力纵向大图
│  └──────────────────────────────────────────────┘    │     每块 240px 高
│  ┌──────────────────────────────────────────────┐    │
│  │  大图 2 根因归因                              │    │
│  └──────────────────────────────────────────────┘    │
├──────────────────────────┬─────────────────────────────┤
│ 典型场景                  │ 数据来源与口径              │
└──────────────────────────┴─────────────────────────────┘
```

**关键改动**

- hero 撑到 280px，右侧放一张真实运行大图，标题与图并排
- 五步流程从文字列表改成横向时间线，节点带序号圆点与连接线，已完成节点填青色
- 三张能力图从三卡并排改为纵向大图，每张下方配一段说明与指标
- 「数据来源」从页脚收进首页右栏，作为产品说明的一部分
- 指标四宫格不再独立出现，改为每张能力图下方的一个数字

**预期结果**：文档总高约 1500px，需要滚动，但对外部观众（评审、答辩演示） storytelling 效果最好。

**改动量**：index.html 大改 + CSS 约 200 行 + 能力图重截（三张纵向大图）。

**风险**：信息密度下降。上一轮刚清掉说明小字，如果这里再加时间线 + 大图，可能重新堆回 AI 味。

### 方案 C · 驾驶舱型

**核心主张**：首页是一块产线监控大屏，第一眼是运行状态与异常，而非产品介绍。

**结构**

```
┌────────┬────────┬────────┬────────┐
│ 94.44% │ 94.68% │ 100%   │ 25.64% │  ← 指标横条置顶，大数字
│ 识别   │ 归因   │ 可执行 │ 闭环降幅│
├────────┴────────┴────────┴────────┤
│ 最新告警（宽栏，5 条）              │ 五步链路状态 │  ← 上半区
│  · 龟裂比例突增（2 件）…            │ ●●○○○      │
├────────────────────────────────────┴──────────────┤
│ 三张能力图横排（截图缩小，做背景纹理）              │
├───────────────────────────────────────────────────┤
│ 典型场景（横向四格，图标在上文字在下）             │
└───────────────────────────────────────────────────┘
```

**关键改动**

- 四个指标做成横贯顶部的 KPI 横条，数字放大到 28px，配趋势箭头
- 告警区扩宽到 2/3，链路状态点缩到 1/3
- 能力图截图缩小到 160px 高，主要作为视觉底纹，文字信息前置
- 典型场景改为横向四格一行排布

**预期结果**：文档总高约 900px，单屏装满，视觉上最接近工业 NOC 大屏。

**改动量**：index.html 中等调整 + CSS 约 150 行 + app.js 约 30 行（KPI 横条渲染）。

**风险**：缺失"这产品是什么"的叙事。评审如果是非质量工程背景，看到一堆数字不知道对应什么能力，反而不如现状。

## 三、方案对比

| 维度 | A 任务优先 | B 叙事门户 | C 驾驶舱 |
|------|------------|------------|----------|
| 首屏信息量 | 高（含进度 + 指标 + 能力图） | 中（大图 + 时间线） | 高（指标 + 告警） |
| 文档总高 | 约 860px | 约 1500px | 约 900px |
| 是否需滚动 | 基本不需要 | 需要 | 不需要 |
| 回答"这是什么" | 一般 | 最强 | 最弱 |
| 回答"现在干什么" | 最强 | 一般 | 一般 |
| 与顶部指引条一致性 | 同一数据源，无冲突 | 无冲突 | 部分重叠（链路状态重复） |
| 与深蓝工业配色契合 | 高 | 中 | 最高 |
| demo 感风险 | 低 | 中（可能堆回说明文字） | 低 |
| 改动量 | 中（120 行 CSS） | 大（200 行 CSS + 全量重截） | 中（150 行 CSS） |
| 适合场景 | 评委实操点击 | 对外展示、答辩演讲 | 工业客户演示 |

## 四、推荐

**推荐方案 A**，理由三条：

1. **和你之前反复提的问题同源**。你多次说"不知道点哪里""闭环不知道咋操作"，根因都是缺一个明确的"现在该干什么"。首页第一屏就放这张进度卡，和顶部指引条共用同一份状态，评审点任何一步首页都跟着变，感知是"活的"。

2. **信息密度已经调到这个方向了，不该回调**。前面几轮已经把首页从"两栏空白 + 空告警块"改到现在这样，B 方案往回加时间线和大图，风险是刚清掉的说明小字重新堆回来。

3. **改动可控且能一次做完**。三张图重截 + 结构调整 + CSS 收敛，改完总高降到 860px 以内，首屏装得下。

如果你倾向 B 或 C，也可以直接说，方案本身可以混合（比如 A 的骨架 + B 的大图 hero）。实施前我会先出静态线框图给你确认，再动代码。

## 五、与 A 方案配套的截图重取清单

不管选哪个方案，三张能力图都得重取，因为现在的图被 CSS 强裁变形了。

| 图 | 取哪个元素 | 目标比例 | 备注 |
|----|-----------|---------|------|
| cap-detect.png | `#result-panel` | 2:1 | 当前 1180×588，基本可用，重取更整齐 |
| cap-attr.png | `.attr-cta` + `#attr-bars` 组合区域 | 2:1 | 当前是 1300×2472 竖图，必须换成横向区域 |
| cap-verify.png | `#cl-band-wrap` | 2:1 | 当前 2012×1328 略宽，裁到 2:1 |

重取时统一用 `device_scale_factor=2` 保证清晰度，总体积控制在 800KB 以内。

## 六、验收标准

改完后逐条核对：

- [ ] 1440×900 视口下，首页无需滚动即可看到进度卡、指标四宫格、三张能力图
- [ ] 页面总高 ≤ 900px（方案 A）/ ≤ 1600px（方案 B）
- [ ] 三张能力图无变形、无关键内容被裁，图中文字可辨认
- [ ] 全页只有一个实心主按钮
- [ ] 进度卡数字与顶部指引条、左栏「进度 N/5」三处完全一致
- [ ] 典型场景与最新告警两栏等高，右侧无大片空置
- [ ] 点击能力卡进入对应页面，浏览器前进后退正常
- [ ] 窄屏（<1100px）下布局降级为单列，内容不溢出

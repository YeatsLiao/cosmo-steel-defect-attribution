# 界面与引导动线优化提示词

三轮提示词，按顺序发。每轮都只改视觉与交互，**不改业务逻辑、不改数据接口、不改页面上的任何数字**。

发之前先说清一件事：这三轮是为了「设计打磨 10 分」和「完整度 25 分」里的体验项。功能已经完整，UI 是加分不是及格线，所以**随时可以停**，不要为了 UI 拖到发布不了。

---

## 第一批 · 密度与工作台瘦身（低风险，优先发）

```text
只改视觉与交互，不要改任何业务逻辑、数据接口和数字。固定约束继续遵守。

1. 全局密度调整：
   body 字号 13px → 14px，行高 1.5 → 1.65
   .panel 内边距 12px 14px → 18px 20px
   卡片/栅格 gap 12px → 16px
   表格行高 32px → 40px，表头与正文区分度加大

2. 检测工作台瘦身：
   这一页只保留「样件输入（上传 + 六类缩略图）」和「识别结果」两块。
   工艺上下文表单整体移到「归因诊断」页——它本来就该在那儿。
   检测记录改成可折叠面板，默认收起，标题显示「检测记录（200 条）」，
   展开后每页只显示 10 条并带翻页。
   归因样例面板删掉（归因诊断页已有）。

3. 识别结果主次分层：
   缺陷类型和置信度用 26px 大字号（置信度主色青），严重等级用状态标签，
   检测框画在原图上，右侧列出 推理耗时 / conf / iou / NMS 保留框数。
   龟裂这一类额外加一行橙色小字「识别难点：龟裂 AP 0.383，此类最难」。

4. 删除 view-placeholder「模块建设中」这个空页面和它在 VIEW_IDS 里的引用。

5. 图表统一：echarts 图表高度 220 → 260px，图例放底部，
   配色只用主色青 #2FD4C4、辅助蓝 #378ADD、警示红 #E24B4A、警告橙 #EF9F27。
```

## 第二批 · 顶部流程条 + 使用说明 + 空态引导（核心动线）

```text
加一套用户引导动线，让第一次进来的人知道先做什么、现在做到哪了、下一步去哪。
仍然不改业务逻辑、数据接口和页面上的数字。

1. 顶部主流程条（放在导航下方，全站常驻，六个页面都有）：
   五步：① 上传样件 → ② 缺陷识别 → ③ 归因诊断 → ④ 生成工单 → ⑤ 闭环验证
   每步一个圆形节点 + 连线，三种状态：
   已完成：实心青色 #2FD4C4，节点内显示对勾
   进行中：深色底 + 青色描边 2px，节点内显示序号，右侧显示「进行中」
   未开始：#12253D 底 + #1E3350 描边，节点内灰色序号
   右侧显示「进度 N / 5」。

2. 状态必须和真实数据联动，不能是装饰：
   ① 完成 = 已上传或载入样件
   ② 完成 = 已有检测结果
   ③ 完成 = 已执行过归因诊断
   ④ 完成 = 工单列表里已存在工单
   ⑤ 完成 = 复检记录里已有数据
   进行中 = 第一个未完成的步骤。
   进度写入 localStorage，刷新页面不丢。

3. 流程条可点击：
   点第①②步跳到检测工作台，③跳归因诊断，④跳整改工单，⑤跳闭环验证。
   已完成的步骤允许回看，跳过去时页面顶部保留当前样本上下文
   （图片名 · 缺陷类型 · 置信度 · 严重等级 · 推理通道）。

4. 右上角「使用说明」按钮（问号图标），点开右侧抽屉，四段内容：

   一分钟上手
   载入示例样件 → 看识别结果 → 填工艺参数执行归因 → 生成整改工单 → 执行复检看降幅。
   全程约 30 秒，不需要任何准备。

   六个页面在做什么
   检测工作台：上传钢材图片，实时识别出六类缺陷
   归因诊断：结合工艺参数，定位根因并给出四维贡献度
   知识库：30 条冶金行业规则，可增删改和启停
   整改工单：把归因结论转成可派发的工单并跟踪状态
   闭环验证：执行整改后复检，验证缺陷率是否下降
   分析看板：全局指标、分布与趋势

   常见问题
   数据哪来的：缺陷图片来自公开的 NEU-DET 学术数据集；工艺参数为模拟生成
   94.44% 怎么算的：180 张测试集图片级 Top-1 准确率，测试集未参与训练
   实时还是离线：检测结果显示「实时推理」或「离线评测结果」标签，以标签为准
   闭环降幅是真的吗：是基于规则库预期降幅的工况推演，页面已标注，接入实测复检数据即为真实

   数据来源与真实性声明
   缺陷检测数据为公开学术数据集，工艺参数与整改效果为企业数据不可得前提下的模拟推演，
   所有模拟内容均已在对应页面就近标注，未冒充真实产线数据。

5. 空态引导：
   检测工作台未检测时，识别结果区域显示引导卡：
   标题「尚未检测」，副标题「按顺序做三件事，大约 30 秒走完全流程」，
   下面三个小步骤标签 ① 选一张示例图 ② 看识别结果 ③ 去归因诊断，
   右侧一个主色按钮「载入示例样件」，点了直接载入第一张示例图。

6. 下一步按钮：
   识别结果卡片底部加「去归因诊断 →」，归因结果底部加「生成整改工单 →」，
   工单列表顶部加「去闭环验证 →」。点击同时更新流程条状态。

7. 首次访问自动弹出一次使用说明抽屉，之后用 localStorage 记住，不再自动弹。
```

**验收**：

- 载入示例图后，流程条第 ①② 步变实心对勾，第 ③ 步变「进行中」，右侧显示「进度 2 / 5」
- 刷新页面进度还在
- 点流程条第 ④ 步能跳到整改工单页
- 右上角问号能打开抽屉，四段内容都在，且和上面文案一致
- 空态引导卡的按钮点了能直接载入示例图

## 第三批 · 表单分组与信息分层（可选，有余力再做）

```text
继续视觉优化，仍然不改逻辑和数字。

1. 归因诊断页的工艺参数表单按 设备参数 / 物料信息 / 人员 / 环境 分成四组，
   用可折叠手风琴，默认展开「设备参数」和「物料信息」两组，
   每组标题右侧显示该组异常项数量（例如「异常 2 项」红色小标）。

2. 归因结果：主因卡片字号加大，候选根因列表默认折叠；
   证据明细表默认只显示「超标」和「临界」的行，正常行收进「显示全部」展开。

3. 知识库 30 条规则：改为每页 12 条分页，卡片间距加大，
   触发条件和解决策略用不同色阶区分（条件灰、策略青）。

4. 窄屏适配：屏幕宽度小于 1100px 时工作台改为单列，不出现横向滚动条。
```

# 009 · 把平台代码推到 GitHub

代码在平台沙箱的 `/workspace` 里，本机没有。所以推送要在**平台那边**做，用任务页的「终端」标签。

---

## 第一步 · 在 GitHub 建一个空仓库（本机浏览器做）

1. 打开 https://github.com/new
2. Repository name 填 `steel-defect-attribution`
3. 选 **Public**
4. 下面三个都**不要勾**：Add a README file、Add .gitignore、Choose a license（勾了会导致推送冲突）
5. 点 Create repository
6. 建好后页面会显示仓库地址，形如 `https://github.com/你的用户名/steel-defect-attribution.git`，记下来

## 第二步 · 生成 GitHub 令牌（PAT）

GitHub 现在不接受账号密码推代码，要用令牌。

1. 右上角头像 → Settings → 最下面 Developer settings → Personal access tokens → Tokens (classic)
2. Generate new token (classic)
3. Note 填 `cosmo-contest`，Expiration 选 90 days
4. 勾选 **repo**（这一个就够，其余不要勾）
5. Generate token
6. **令牌只显示这一次**，复制保存（ghp_ 开头）

这个令牌和平台的 GIT Token 不是一回事，别混。

## 第三步 · 在平台终端推代码

回到平台任务页 https://code.cosmoplat.cn/console/task/9a59535e-a3ee-4dbc-8c41-5d79ae2ad44f ，点上面的「终端」标签，把下面这段**整段粘贴**执行。

先把前三行换成你自己的信息：

```bash
cd /workspace

git init
git config user.name "你的GitHub用户名"
git config user.email "你的GitHub邮箱"

cat > .gitignore <<'EOF'
.env
.env.*
__pycache__/
*.pyc
runs/
annotated/
*.log
node_modules/
.venv/
EOF

git add -A
git status
```

执行完先看一眼 `git status` 的输出，**确认列表里没有 `.env`**——那个文件里有飞书 Webhook 地址，推上去等于把告警通道公开了。有的话说明 .gitignore 没生效，先停下拉我。

确认没问题再执行：

```bash
git commit -m "feat: 钢材表面质量缺陷智能归因与闭环处置平台

- YOLOv8n FP16 ONNX 实时缺陷检测（六类，94.44%）
- 四维根因归因引擎 + 30 条冶金规则库（94.68%）
- 整改工单流转与闭环复检推演（降幅 25.64%）
- 分析看板与飞书告警推送"

git branch -M main
git remote add origin https://你的用户名:你的令牌@github.com/你的用户名/steel-defect-attribution.git
git push -u origin main
```

`git remote add` 那一行把「你的用户名」和「你的令牌」都替换掉，令牌就是刚才 ghp_ 开头那串。地址里带令牌是为了省去输密码，推完可以在 GitHub 把令牌删掉。

## 第四步 · 验证

浏览器打开 `https://github.com/你的用户名/steel-defect-attribution`，能看到 `app.py`、`detector.py`、`static/`、`model/`、`knowledge_base.json` 这些文件就成了。

然后补一个 README（在 GitHub 网页上点 Add a README 直接写，不用再推一次）：

```markdown
# 钢材表面质量缺陷智能归因与闭环处置平台

面向钢铁表面质量管控的缺陷识别、根因归因与整改闭环一体化应用。

在线体验：https://8000-6756f5ede07e02c3.code.cosmoplat.cn/
（应用由 COSMO Code 平台生成与托管）

## 能力

- 缺陷识别：YOLOv8n，NEU-DET 六类缺陷，FP16 ONNX 实时推理，单张约 12 ms，图片级 Top-1 准确率 94.44%
- 根因归因：设备 / 物料 / 人员 / 环境四维贡献度 + 30 条冶金规则库，根因定位准确率 94.68%
- 整改闭环：工单流转 + 复检推演验证，缺陷率降幅 25.64%，改进建议可执行率 100%
- 分析看板：缺陷分布、严重等级、根因维度、月度趋势、Top 根因
- 告警推送：严重缺陷实时推送飞书

## 数据来源与真实性说明

缺陷图片来自公开学术数据集 NEU-DET，测试集 180 张未参与训练。
工艺参数与整改效果为企业数据不可得前提下的模拟推演，用于验证归因与闭环逻辑，不是真实产线数据。
龟裂类 AP 0.383，为六类中识别难度最高的一类。
```

## 如果推不动

沙箱访问 GitHub 可能超时。表现是 `git push` 卡住或报 `Failed to connect`。

处理方式：

- 先重试一次，有时是瞬时网络
- 仍不通就改推 Gitee（gitee.com 建同名公开仓，地址换成 `https://gitee.com/用户名/steel-defect-attribution.git`，令牌在 Gitee 设置 → 私人令牌里生成），评审只认"有开源仓链接"，Gitee 同样有效
- 不要反复重试超过三次，浪费时间

推完这一步，回到 008 文档继续发提示词改界面。这两件事不冲突。

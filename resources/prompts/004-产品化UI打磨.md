# 004 · 产品化 UI 打磨提示词

目标：把应用从「功能齐备的演示页」提升到「像一个正式上线的产品」。

003 之后是本文的第四 ~ 第六批，005 是第七 ~ 第八批。三批提示词，按顺序发，每发一批等改完验收再发下一批。仍然只改视觉与交互，**不改业务逻辑、不改数据接口、不改页面上的任何数字**（唯一例外：批次一第 3 条是修流程条状态 bug，允许动状态逻辑，但不许动业务数据）。

每批改完都截图存档，这是「使用深度 20 分」的证据。

---

## 第四批 · 全局框架产品化（最优先，解决六页共性问题）

```text
只改视觉与交互，不改业务逻辑、数据接口和任何数字。固定约束继续遵守。本轮把全站框架调整为正式产品的样子：

1. 品牌区（左上角）：
   标题前加一个 28×28 的内联 SVG logo（盾牌内含对勾，主色青 #2FD4C4 描边、透明底），
   标题「钢材表面质量缺陷智能归因与闭环处置平台」字号降到 16px，旁边加一个小号灰色徽标「v1.0」。
   导航选中态加强：选中项文字变纯白 + 底部 2px 青色条 + 背景微亮 #142943；hover 时文字变亮并带 0.2s 过渡。

2. 告警条收纳（六页共用那块红色高危告警）：
   从页面常驻区移除，改为导航栏右侧一个铃铛图标按钮，带红色圆点徽标显示告警数（5）。
   点击展开下拉面板，面板内容与样式沿用现在的告警条（输出严重缺陷、龟裂检出、现场 24 小时内出现 5 次），
   面板底部保留「推送告警通知」按钮。
   只有检测工作台和分析看板这两个页面，仍在顶部保留一条精简版告警横条（单行，可点击 × 收起，收起状态记住）。

3. 修复流程条状态 bug（本轮唯一允许动逻辑的地方）：
   现在刚进应用就显示「生成工单」「闭环验证」两步已完成，与「进度 2 / 5」自相矛盾。
   修复规则：五个步骤的完成状态必须且只能由真实动作触发——
   ① 载入或上传样件 ② 有检测结果 ③ 执行过归因 ④ 工单列表存在 ⑤ 复检记录存在。
   localStorage 的 key 加版本号（如 flow_v2），版本不匹配时重置为初始状态。
   初始状态必须是：第①步「进行中」，其余四步未开始，进度 0 / 5。

4. 指标卡收纳：
   四张指标大卡（94.44% / 94.68% / 100% / 25.64%）只在「分析看板」页保留完整大卡。
   其他五个页面改成导航下方一行紧凑胶囊条：四个胶囊并排，
   每个胶囊格式为「指标名 94.44%」，数字青色，高度 32px，可点击跳转到分析看板。
   「指标来源：离线评测（platform_data.json），非实时计算」这行小字只在分析看板保留。

5. 当前样本条收纳：
   「当前样本：未选择样件…」这条只在检测工作台和归因诊断两页显示，
   且选中样件之前不显示，选中后才出现（内容：图片名 · 缺陷类型 · 置信度 · 严重等级）。

6. 使用说明抽屉不再自动弹出：
   删掉「首次访问自动弹出」逻辑。
   改为：首次访问时，在右上角问号图标旁显示一个小气泡「第一次用？30 秒上手 →」，点击打开抽屉；
   点过之后气泡永久消失（localStorage 记住）。

7. 页脚：
   每页底部加统一页脚，一行居中小字灰：
   「钢材表面质量缺陷智能归因与闭环处置平台 · 缺陷图片来自公开 NEU-DET 数据集，工艺数据为模拟推演并已就近标注 · © 2026」
```

**验收**：进应用时流程条 0/5、只有第①步进行中；铃铛带红点 5；其他页顶部没有大告警条和四张大卡；选中样件前没有当前样本条；问号旁有小气泡；页脚在。

## 第五批 · 各页信息层级与卡片质感

```text
继续视觉优化，不改业务逻辑、数据接口和数字。本轮逐页调整信息层级：

1. 检测工作台 · 样件输入：
   六类缩略图改为 3 列 × 2 行网格，每格统一为卡片：上图（160px 高，object-fit:cover），
   下行左侧类名（白色 13px）右侧英文小灰字，卡片圆角 8px、描边 #1E3350，hover 时描边变青并微微上浮。
   「上传图片」改为实心主色按钮，「载入示例样件」描边按钮，两个按钮并排同高。

2. 归因诊断页：
   未选样件时，表单区上方显示引导卡：标题「先选一个样件」，副标题「选择缺陷类型与批次后载入，工艺参数会自动填充示例值」。
   「执行归因诊断」按钮升级为实心主色大按钮（高 40px），放在表单组下方通栏。
   手风琴分组保留，组标题字号 14px 加粗，展开箭头对齐。

3. 知识库页：
   每张规则卡右上角的「启用」改为状态开关样式（青色为启用），
   「删除」按钮从卡片上移除，收进「编辑」弹层内作为危险操作（红色描边 + 二次确认文案）。
   卡片内字段名（缺陷类型/根因/触发条件/解决策略/预期降幅）统一灰色小字 12px，值 13px 白色，
   解决策略保留青色。筛选下拉与「新增规则」按钮同一行右对齐。

4. 整改工单页：
   工单卡片的字段改为两列对齐网格：左列（工单号、主题、整改措施）右列（缺陷类型、根因维度、责任人、状态）。
   空值统一显示灰色「—」并配 tooltip「暂无关联记录」，不要裸露。
   状态标签标准化：待处理灰 / 处理中橙 / 已完成青 / 已关闭深灰，统一圆角胶囊。
   筛选区（状态、维度、去闭环验证按钮）合并为一行，按钮右对齐。

5. 闭环验证页：
   「复检设置」区加标题图标与说明文案排版：批次数下拉和样本量输入框等宽对齐，「执行复检」实心主色按钮。
   整改措施清单卡片：勾选框、措施名、预期降幅对齐一行，底部固定「执行推演」主按钮。

6. 分析看板页：
   四张 KPI 大卡加图标（计检统计/缺陷率/处置时长/闭环达标率，线性图标青色）。
   「平均处置时长 0.0 h」若数据为空，大数字显示「—」，副文案改为「暂无已闭环工单数据」。
   三个环形图配色收敛为四色规范：主色青 #2FD4C4、辅助蓝 #378ADD、警告橙 #EF9F27、警示红 #E24B4A，
   其余扇区用 #1E3350 深灰，图例统一放底部横排。
```

**验收**：样件是整齐 3×2 网格；知识库卡上没有红色删除按钮；工单空值显示「—」带提示；看板饼图只有四种颜色加深灰。

## 第六批 · 细节质感与微交互

```text
最后一轮细节打磨，不改业务逻辑、数据接口和数字：

1. 按钮体系统一（全站）：
   主按钮：实心青底 #2FD4C4 深色文字（如 执行归因诊断 / 执行复检 / 推送告警通知）
   次按钮：透明底 + #1E3350 描边 + 白字（如 载入示例样件 / 载入）
   危险按钮：红色描边红字（删除类）
   所有按钮高 34px、圆角 6px，hover 亮度提升带 0.2s 过渡，禁用态 40% 透明度。

2. 卡片统一规格：
   所有 .panel 圆角 10px、背景 #142943、描边 1px #1E3350，
   标题行统一 14px 白色加粗，不加竖条、不加色块装饰，右上角允许放轻量操作。
   卡片阴影 0 2px 8px rgba(0,0,0,0.25)。

3. 输入框统一：
   所有 input/select 高 34px、背景 #0E1B2E、描边 #1E3350、圆角 6px，
   focus 时描边变青并带 0 0 0 2px rgba(47,212,196,0.15) 外圈，transition 0.2s。

4. 全局微交互：
   页面切换时主内容区 0.25s 淡入；卡片 hover 上浮 2px；
   表格行 hover 背景 #1A2C46；滚动条改为 6px 细条深灰。

5. 加载与反馈：
   「执行归因诊断」「执行复检」点击后按钮内显示加载态（转圈图标 + 文案不变），
   完成后右上角弹出 toast（成功青色 / 失败红色，2.5 秒自动消失），不再用 alert。

6. 窄屏适配：屏幕宽度小于 1100px 时，导航可横向滚动、指标胶囊条可换行、工作台改单列，不出现横向滚动条。
```

**验收**：全站按钮只有三种样式；点执行归因有加载转圈和 toast；表格行有 hover；窄窗口不出横向滚动条。
